# Project 6 — A personal graphics exhibition

**Prerequisites:** the complete core. **Working references:** the course website itself, material/ocean/instancing/picking labs, and the WebGPU studies. **Goal:** communicate an original visual idea through a reliable interactive experience.

## Build sequence

Write a brief and choose one principal rendering path. Use Three.js when scene composition and asset handling dominate; use native WebGPU when a custom compute pipeline is central. Keep a lower-capability experience readable and useful.

Compose one focal scene with two or three meaningful interactions. Use motion, lighting, geometry, and text to explain the idea. Avoid adding features solely because they appeared in a chapter. Put technical parameters behind a useful teaching or creative control.

Add a short “how it works” view with coordinate diagrams, a few equations, and links to the relevant source modules. Preserve accessible HTML navigation and a nonmoving presentation. Package assets and their provenance with the source.

## Reference solution and explanation

Graphics Atelier is a complete example of a static lesson/gallery application with dynamically loaded GPU modules, responsive layout, source inspection, math rendering, search, local completion marks, and cleanup between scenes. Its individual visual studies are complete, editable starting points rather than a mandatory final aesthetic.

## Finish criteria

Verify the built production output, keyboard flow, phone layout, capability messages, loading behavior, and resource lifecycle. Record performance on representative hardware and camera views. Explain the math and approximations behind the focal effect in your own words.

## Extension

Write a short case study showing initial intent, final image, one difficult bug, the evidence used to diagnose it, and one measured performance tradeoff. That explanation demonstrates transferable fluency more clearly than a list of library names.
